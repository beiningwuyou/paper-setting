# Paper Setting v1.1 架构与技术规范 (双视图模式)

本文档定义 Paper Setting v1.1 的双视图架构、离线隔离与 Agent 协作契约、有限状态机（FSM）以及组件规范。

---

## 1. 双视图系统架构

```text
                                [用户浏览器 (Client)]
                                         |
                       +-----------------+-----------------+
                       | 顶部全局模式切换 (Segmented Control) |
                       +-----------------+-----------------+
                                         |
                 +-----------------------+-----------------------+
                 |                                               |
       [默认视图：极简排版]                             [手动视图：详细与 Agent 智排]
   (Minimalist Local Engine)                       (Detailed & Agent-Assisted)
                 |                                               |
                 v                                               v
     +-----------------------+                       +-----------------------+
     |   4 步直觉向导流      |                       |   高阶排版控制台      |
```

## 2. 模式契约与隔离规范

### 2.1 极简排版模式（默认契约）
1. **网络与传输**：
   - 严格绑定本地回环网络 `127.0.0.1`。
   - 前端禁用任何外部分析、遥测或三方 CDN。
2. **算力与 Agent 隔离**：
   - 彻底跳过 Agent 审核流程，不启动任何大模型推理进程。
   - 计划批准阶段（`approve`）由前端本地运行时全自动合成，将所有置信度合规项批量应用。
3. **性能指标**：
   - 10 万字文档全流程处理耗时 $< 3$ 秒。
   - 内存占用 $< 80$ MB。

### 2.2 详细与 Agent 智排模式（按需契约）
1. **Agent 接入权限门控**：
   - 仅在用户明确点击使用规范推导、深度引注修复或开启 Agent 质检时，方才触发 Agent 进程。
2. **安全可撤销原则**：
   - 每一个由 Agent 推荐或生成的深层重构操作（例如删除文末参考文献、引注改写为脚注），均单独标记 `execution_scope: controlled_ooxml_rewrite`。
   - 用户在 Diff 界面可单键撤销任意一项 Agent 建议。

## 3. 有限状态机 (Finite State Machine)

### 3.1 状态转移表

| 源状态 | 触发事件 | 极简模式行为 (Minimalist) | 详细模式行为 (Detailed + Agent) |
| :--- | :--- | :--- | :--- |
| `IDLE` | 拖入论文初稿 | 检验格式 $\rightarrow$ `DOC_READY` | 检验格式 $\rightarrow$ 启动结构拓扑预检 $\rightarrow$ `DOC_READY` |
| `DOC_READY` | 选择目标标准 | 解锁【一键排版】 $\rightarrow$ `TARGET_READY` | 解锁【分析并生成计划】或【Agent提炼规范】 |
| `TARGET_READY` | 点击开始按钮 | 提交任务 $\rightarrow$ `ANALYZING` | 提交任务 $\rightarrow$ 启动 Agent 深度诊断 |
| `ANALYZING` | 后台就绪 `plan_ready` | **自动安全授权** $\rightarrow$ 直入 `FORMATTING` | **暂停并等待用户交互** $\rightarrow$ 进入 `PLAN_REVIEW` (展示 Diff) |
| `PLAN_REVIEW` | 用户/Agent 确认 | 不经过此状态 | 用户逐项勾选/Agent审核后提交 $\rightarrow$ `FORMATTING` |
| `FORMATTING` | 格式注入完成 | 自动完整性自审 $\rightarrow$ `COMPLETED` | 触发 Codex Agent 二次质检 $\rightarrow$ `AGENT_AUDITING` |
| `AGENT_AUDITING`| Agent 审校完毕 | 不经过此状态 | 整理 Agent 批注清单 $\rightarrow$ `COMPLETED` |
| `COMPLETED` | 交付就绪 | 呈现极简下载大卡片 | 呈现下载、完整 Diff 报告与 Agent 建议列表 |

## 4. UI 设计与模式切换规范

### 4.1 顶部模式选择器 (Mode Segmented Control)
位于页面顶部居中或右上角，形态为现代胶囊切换器：
- **左侧胶囊**：`🌿 极简排版 (默认)` —— 配副标“纯本地 · 断网可用 · 零Agent”。
- **右侧胶囊**：`⚡ 详细与 Agent 智排` —— 配副标“复杂格式攻坚 · 借助 Agent 能力”。

### 4.2 极简视图视觉特征
- **安全色调**：以古雅的纸质白（`#fffdfa`）与常青绿（`#1c5d43`）为主。
- **界面元素**：仅保留 4 步步骤条、上传卡片、目标卡片与主行动大按钮。
- **零干扰**：无任何代码块、无 JSON 输入框、无置信度百分比提示。

### 4.3 详细视图视觉特征
- **控制台质感**：增加了右侧透视抽屉、左侧深层特征指示牌（OMML公式、正文引注、交叉引用域）。
- **Agent 标识**：在涉及 AI 辅助的卡片处带有 `✨ AI Agent 协同` 紫蓝色呼吸微光标签。
- **Diff 对比器**：清晰的“修改前 vs 修改后”双栏卡片，直观展示字体、磅值、缩进差异。
