# 🔬 Paper Setting 进阶技术规格与深度架构说明

本文档详细记录了 Paper Setting 底层针对 OOXML 解析、学校 DOCX 模板合成、深层 Word 结构处理及分层排版策略的实现技术细节。

---

## 🔬 进阶工程规格：学校模板分析与 OOXML 深度特性

### 1. 从规范生成规则包

在“新建排版任务”中展开“从规范文本或文件生成规则包”，可以粘贴文本或上传
UTF-8 `.txt`、`.md` 及 `.docx`。生成器当前支持：

- A4、纵横向、上下左右边距、页眉和页脚距离。
- 论文题目、摘要、关键词、一至三级标题、正文、图表题、参考文献和表格正文。
- 中英文字体、中文字号、磅值字号、加粗、对齐、缩进、段前后、分页控制和三类行距。
- “注释/引注/尾注转脚注”、“删除/不列文末参考文献”、“每页重新编号”和“带圈数字”等深层结构要求。

例如：

```text
页面采用 A4 纸，纵向，上下边距 2.5cm，左边距 3cm，右边距 2.5cm。
正文：宋体，小四，Times New Roman，1.5 倍行距，首行缩进 2 字符，两端对齐。
一级标题：黑体，三号，加粗，居中，段前 12 磅，段后 6 磅。
注释一律采用脚注，文末不列参考文献。每页脚注重新编号，编号格式为带圈数字。
```

该功能不调用外部模型；没有明确识别的文本会显示为警告，规则必须经用户确认后才导入。

规则提取本身仍不调用外部模型。默认配置下，排版及完整性验证完成后会调用本机
Codex CLI 进行一次只读复核。Agent 只能读取成品、规则包、验证报告和执行记录，不能
修改文档；其意见保存为 `output/agent-audit.json`，失败或超时不会撤销已经通过确定性
验证的成品。可设置 `PAPER_SETTING_AGENT_AUDIT_ENABLED=false` 关闭，因此该阶段开启时
会单独消耗 Agent Token。

### 学校模板分析

在“新建排版任务”中展开“分析学校 DOCX 模板”，上传官方 `.docx` 模板后可查看：

- 分节、页面设置、页码格式及首页不同设置。
- 页眉页脚引用与继承情况。
- 样式定义、实际使用次数和高置信度语义映射候选。
- 跨 Run 的 `{{field.name}}`、`[[field.name]]`、`<<field.name>>` 占位符。
- 内容控件标签、Word 字段、书签和文本框数量。
- 当前已经支持和仍待开发的模板能力。

分析阶段不会修改用户模板。对识别出的字段，可填写值并先生成可审核计划，然后下载新 DOCX 副本：

- 支持正文、页眉页脚和文本框中跨 Run 的 `{{field.name}}`、`[[field.name]]`、`<<field.name>>` 占位符。
- 支持按标签或别名写入普通 Word 内容控件。
- 填写计划绑定模板 SHA-256、值哈希和目标数量；模板或值变化后拒绝执行陈旧计划。
- 输出会验证部件清单、未修改部件字节、字段/公式/图形/修订数量，并重新打开 DOCX。
- 数据绑定、嵌套或包含字段、公式、图形和修订的内容控件会被拦截，不会部分写入。

分节结构面板还可以：

- 按节设置 `decimal`、`lowerRoman`、`upperRoman`、`lowerLetter` 和 `upperLetter` 页码格式。
- 设置、清除起始页码，实现前置页与正文分别重启编号。
- 控制每节首页不同和全文奇偶页不同。
- 将页眉页脚改为继承前一节，或将有效页眉页脚、关系文件和嵌入对象引用复制为独立部件。
- 保留原有部件与媒体字节，并对新增部件、关系和内容类型执行白名单验证。

目前字段值为单行文本。模板字段填写与分节结构修改可分别执行，也可通过组合执行接口一次性填入字段并同时设置分节页码、页眉页脚，产出一个 DOCX 副本；组合执行在内存中先填写字段再克隆页眉页脚部件，确保克隆的部件携带已填充内容。

在新建任务时额外上传学校模板，会进入整篇模板合成流程：

- 原稿仍保存为只读 `input/source.docx`，学校模板保存为只读 `input/template.docx`，两者都不被原地修改。
- 模板使用独立段落 `{{document.body}}`、`{{正文}}`（也支持 `[[...]]` 与 `<<...>>`）标记正文注入位置。
- 标题、摘要、关键词、作者/姓名、学号、学校、学院、专业和导师支持常见中英文键名；规则包显式值优先于语义推断，无法可靠映射的字段保持未填写并在计划中显示。
- 若已可靠映射封面字段，注入正文从第一个一级标题开始，避免标题、摘要和关键词在封面与正文中重复。
- 注入时复制正文段落、表格、自定义样式、列表编号、公式、图片和超链接；原稿分节属性被移除，使页码、页眉页脚和奇偶页继续由学校模板控制。
- 字段映射、正文注入和分节结构作为同一个计划整体审批、原子执行，并验证原稿/模板未变、正文文本、图片、结构设置和 Word 可重开性。

### 深层 Word 功能

工作台内置了 `zh-thesis-deep` 规则包。它在通用排版基础上启用：

- 将 OMML 数学字体统一为 Cambria Math，并重构公式运行样式。
- 将 `[3，1, 2, 2]` 等明确数字引用规范为 `[1–3]`。
- 建立或更新 `TOC` 域、标题大纲级别与 `updateFields`。
- 将一至三级标题、图表题和参考文献条目绑定到 Word `numbering.xml`，并可移除已有文本编号。
- 将显式图表目标与引用标记编译为 Word 书签、`SEQ`、`REF` 和 `PAGEREF` 域，并在打开文档时请求 Word 更新域。
- 将 Word 尾注转为脚注；将正文 `〔n〕`、`[n]`、`【n】` 引注按第 n 条文末参考文献生成真实 Word 脚注，并可删除最后的参考文献区。
- 可将脚注编号设置为逐页从 1 重新开始，并由 Word 使用带圈数字编号；生成的脚注段落左对齐，允许西文在单词中间换行。

深层操作不默认作用于未启用相应规则的规则包，必须在计划页显式确认。每个规则包都使用同一份 `advanced.notes` 契约；从规范文本生成规则包时会自动写入该契约。转换前会校验全部引用序号均有对应参考文献，不能完整映射时整项失败且不发布半成品。文本节点、字段指令和受保护对象的计划内变化会记入操作 artifact，验证器不会把一般性内容变化直接放行。

交叉引用使用不会与普通论文正文混淆的显式标记。目标键必须唯一，并以 `fig-` / `figure-`（图）或 `tab-` / `table-`（表）开头：

```text
正文参见[[xref:fig-system]]，所在页为[[xref-page:fig-system]]。

[[xref-target:fig-system]]系统架构
```

启用 `advanced.cross_references.enabled` 后，目标标记会生成书签及“图/表 + SEQ 序号”，普通引用生成带超链接的 `REF` 域，页码引用生成带超链接的 `PAGEREF` 域。目标标记必须位于题注段落开头并带有题注文字；默认会移除标记后已有的“图 2-3”或“表 2-3”等旧编号。SEQ 管理的题注不会再绑定列表编号，因此重复执行或同时启用自动编号也不会产生双重编号。重复目标、未解析引用、拼写错误、非法键前缀或位于字段、公式、修订等受保护结构中的标记会阻塞计划，系统不会发布部分转换的文档。

### 规则包中的模板配置

规则包顶层可以携带 `template` 配置，让能力门自动评估模板填写与分节结构是否可执行：

```json
{
  "template": {
    "fill": {
      "values": {
        "student.name": "张三",
        "school.name": "示例大学"
      }
    },
    "structure": {
      "even_and_odd_headers": true,
      "sections": [
        {
          "section_index": 1,
          "page_number_format": "decimal",
          "page_number_start": 1,
          "header_mode": "independent_copy",
          "footer_mode": "independent_copy"
        }
      ]
    }
  }
}
```

- `template.fill.values`：按占位符或内容控件标签填写的键值。非空时门要求 `template.fill` 与 `template.placeholders`。
- `template.structure`：分节页码、起始值、首页/奇偶页及页眉页脚链接关系。非空或设置全局奇偶页时门要求 `sections.page_numbering` 与 `sections.headers_footers`。
- 两者均可省略；省略时不会要求对应能力，符合旧规则包。能力报告据此在导入时给出 `required / supported / blockers`，可执行性检查不变。

### 模板驱动任务

如果用带 `template` 配置的规则包创建任务，或在创建任务时额外上传学校模板，任务会自动进入 **template 模式**。Worker 生成字段填写、可选整篇正文注入、分节页码与页眉页脚组合计划；用户在 Web 中整体审批后执行一次原子生成，产出一个 DOCX 副本并记录 `template_plan`、`template_docx`、报告与审计材料。既无模板配置也未上传学校模板的规则包保持原有 format 模式（PatchPlan 逐项审批）。

- `POST /api/v1/templates/combined/preview` 与 `POST /api/v1/templates/combined`：工作台内直接组合预览与生成。
- `POST /api/v1/jobs` 可传可选的 `template_document`；它或规则包模板配置会自动设置 `mode=template`。`GET /api/v1/jobs/{id}/template-plan` 读取组合计划，审批后 Worker 完成组合执行。
- `GET /api/v1/jobs` 使用稳定游标分页读取历史；`DELETE /api/v1/jobs/{id}` 只删除 completed / failed / cancelled 任务，并清理其全部本地数据。
- MCP 的 `create_job` 支持可选 `template_input_path`，并提供 `list_jobs` 与 `get_template_plan`；计划仍必须由用户在 Web 中确认。

## 验证

排版与安全问题的本地回归可直接运行 `python3 scripts/check.py`；全量 Python 验证运行
`python3 scripts/check.py --full`。入口先核实 `.venv` 是否指向当前源码，不启动服务或
处理用户文稿。日志和 `result.json` 保存在新的 `artifacts/checks/` 子目录中；可用

`pyproject.toml` 的覆盖率门槛。缺少依赖时按“安装与运行”中的方式恢复，不盲目重复测试。

## 安全执行边界

公式、字段、文本框、浮动对象、修订、嵌套与复杂合并表格会被检测并标记为需复核。用户显式确认后，系统会调整页面、段落、样式和普通文字 Run，但不重写这些对象的内部 XML。完整性验证失败时仍不会发布成品。

整篇模板合成遇到脚注、尾注、批注、OLE、AltChunk 或尚不能无损迁移的图表关系时会在计划阶段阻断，不生成部分成品；普通公式、图片、表格、字段文本与超链接可以保留。当前仍不猜测引用文献的作者/年份语义，不会从无结构文本自动反推国标条目；也不做 WYSIWYG 编辑、账户系统或 Windows Word COM 自动化。
# 分层排版策略

普通文稿任务默认使用 `formatting_mode=standardize`：规则包明确属性优先，
未规定属性由默认基线补齐，仍未覆盖的角色保留原格式并提示复核。
`formatting_mode=preserve` 仅应用规则包明确属性；未规定的继承格式也保留。
明确的 `false` 和 `0` 是有效规则，不会被基线覆盖。

默认基线目前是**过渡配置，不是最终论文模板**，复用原有通用角色格式并补齐
普通段落颜色与间距；不自动处理表格内部、页眉页脚、未知角色或深层 Word 结构。
现有学校 DOCX 模板注入是独立流程，不套用此基线。

后续选定模板时，可设置 `PAPER_SETTING_DEFAULT_BASELINE_PATH` 指向符合 RulePack
格式的本地 JSON。只读取其页面与角色格式，深层操作仍须由规则包明确开启。
基线应设置独立 ID、名称和版本；无需修改排版引擎。
每个新任务保存 `formatting-policy.json` 快照，审批计划包含策略与属性来源，
更换基线不会影响已创建任务。原有无快照任务继续使用原流程。

规则包的 `explicit_page_fields` 保存明确页面字段；从规范提取的新规则包不会
再把缺项伪装成显式默认值。旧 JSON 若已写满页面字段且无此元数据，只能视为全部
明确指定；如这些值原先由系统补齐，请重新提取规范以恢复准确来源。

结果报告提供实际应用的规则包/基线属性数量、基线提示及未覆盖角色。
低置信度识别及受保护 Word 对象继续要求人工确认，不承诺自动修复所有打乱结构。
